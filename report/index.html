机器人 Agent Harness：现状与缺口Robot Agent Harnesses: Where the Field Stands

当前机器人 Agent 已经能调用 ROS 技能或 VLA 策略；同时接入两类后端、并依据任务状态显式路由的项目仍然偏少。 Current robot agents can already call ROS skills or VLA policies. Far fewer systems connect both backends and route between them explicitly from task state.

Overview

Agent loop 已成为常见结构Agent loops are now common

深度样本都把机器人能力封装成 skill，由 LLM 循环调用。区别主要在动作单元：skill graph、子任务、单次 tool call、MCP skill。 The deep-dive systems wrap robot capabilities as skills under an LLM loop. The unit of action differs: a skill graph, a subtask, a single tool call, or an MCP skill.

02

记忆是主要差异点Memory is the differentiator

3D 场景图（HoloAgent-0）、带位姿的观测（DimOS）、场景摘要 + 工具经验（Thea）、多机共享记忆（RoboOS）。 3D scene graphs (HoloAgent-0), pose-stamped observations (DimOS), a scene brief with tool experience (Thea), and memory shared across robots (RoboOS).

03 · 缺口the gap

显式 ROS / VLA 路由仍是少数Explicit ROS / VLA routing is still uncommon

Thea 已让 Agent 在多个 VLA 工具间选择，是最接近的深度样本；OpenRAL、RoboNeuron 与 Cyclo 也让 ROS 和 VLA 共存。但基于能力、风险与历史成功率进行在线路由，公开实现仍不成熟。 Thea already lets an agent choose among VLA tools and is the closest deep-dive example; OpenRAL, RoboNeuron and Cyclo also combine ROS and VLA. Public implementations of online routing based on competence, risk and prior success remain immature.

02Landscape

Landscape

横轴表示动作主要由确定性 ROS 技能还是学习型 VLA 策略执行；纵轴表示运行时维护世界状态、记忆、验证与恢复的深度。多数项目强化其中一侧，同时兼顾两类后端和完整闭环的工作仍较少。 The horizontal axis shows whether actions are executed mainly by deterministic ROS skills or learned VLA policies. The vertical axis shows how deeply the runtime maintains world state, memory, verification and recovery. Most projects strengthen one side; few combine both backends with a full closed loop.

本次调研的核心判断Central finding

问题已经不再是“能不能把 ROS 和 VLA 都做成 Skill 给 LLM 调用”，而是如何可靠地完成异构控制器选择、阶段性交权、执行监控、失败恢复、世界状态更新，以及基于经验的动态路由。 The question is no longer whether ROS and VLA can both be exposed to an LLM as skills. It is how to make heterogeneous controller selection, phased handoff, execution monitoring, failure recovery, world-state updates and experience-driven dynamic routing reliable.

RoboClaw：从机器人 API 走向可恢复的 Agent RuntimeRoboClaw: from robot APIs to a recoverable agent runtime

目标不是再做一个聊天式控制入口，而是让机器人在长程任务中持续理解世界、选择执行方式、验证结果，并从经验中变得更可靠。 The goal is not another chat control surface, but a runtime that understands the world, selects execution backends, verifies outcomes and becomes more reliable through experience.

总体方向：General direction:以统一世界状态为基础，把 Agent 决策、Skill Graph、ROS/VLA 混合执行、验证恢复和经验演化串成一个闭环。build one closed loop over a unified world state: agent decisions, skill graphs, hybrid ROS/VLA execution, verification and recovery, then experience-driven evolution.

Thea

把 coding agent 的 harness 搬到机器人上：策略即工具，场景图即上下文，评估即退出码。 The coding-agent harness applied to robots: policies as tools, scene graph as context, evaluation as exit codes.

VLA 即工具VLAs as tools 评估器Evaluator 工具经验Tool experience

核心机制Core mechanism

LLM 每轮只调用一个工具，工具背后是封装好的策略（π0.5、ACT、LingBot-VLA）；每个动作后由 VLM 评估器返回“成功 / 失败 / 进行中”。 The LLM makes one tool call per turn over wrapped policies (π0.5, ACT, LingBot-VLA). After each action a VLM evaluator returns success / failure / in-progress.

直接启发Direct lesson

唯一把 VLA 当一等工具、并有实测验证器（准确率 93.3%）的系统。 The only system with VLAs as first-class tools and a measured verifier (93.3% accuracy).

局限Limitations

没有显式规划；选哪个策略全靠 LLM 读工具描述；评估器带来延迟；不涉及 ROS。 No explicit plan. Policy choice is left to the LLM reading tool descriptions. The evaluator adds latency. No ROS.

Hi-VLA Design Study

VLM 规划器编排 VLA 控制器时，哪些设计真正重要：一项受控消融研究。 What matters when a VLM planner orchestrates VLA controllers: a controlled ablation study.

VLM → VLA 消融Ablation ALOHA

研究问题Research question

在仿真和真实 ALOHA 上，消融规划器推理、VLA 可控性、观测形式、记忆与终止条件。 Ablates planner reasoning, VLA steerability, observation format, memory and termination, in simulation and on a real ALOHA.

硬数据给出的答案What the numbers say

有硬数据：长程任务 67.08% vs 25.30%（扁平 VLA）；成功检测是最好的终止方式，由 VLM 判定终止最差。 Hard numbers: 67.08% vs 25.30% (flat VLA) on long-horizon tasks. Success detection is the best termination rule and VLM-decided termination the worst.

局限Limitations

只有 VLA：没有 ROS 分支、没有导航、没有世界记忆。 VLA-only: no ROS branch, no navigation, no world memory.

05缺口Gap

关键挑战：异构控制器如何在闭环中可靠协作？The key challenge: how can heterogeneous controllers work reliably in a closed loop?

把 ROS 与 VLA 封装成 LLM 可调用的 Skill 已有多种实现；真正尚未成熟的是从选择、交权和监控到恢复、状态更新与经验反馈的完整闭环。 Several systems already expose ROS and VLA as LLM-callable skills. What remains immature is the full loop spanning selection, handoff and monitoring through recovery, state updates and experience feedback.

需要回答的问题The question to answer

如何让 Agent 在 ROS 与 VLA 等异构控制器之间可靠选择、阶段性交权，并在执行过程中持续监控、恢复和更新世界状态？ How can an agent reliably choose and hand off between heterogeneous controllers such as ROS and VLA, while continuously monitoring execution, recovering from failure and updating world state?

各系统目前的做法How each system answers it today
  • HoloAgent-0固定Fixed 每类技能在设计时绑定一个后端。Each skill type maps to one backend at design time.
  • RoboOS另有侧重Elsewhere 它选择的是“哪台机器人”，而不是“哪种后端”。It chooses which robot, not which backend.
  • Thea隐式Implicit 由 LLM 根据工具描述与经验笔记选择策略工具。The LLM picks a policy tool from descriptions and experience notes.
  • DimOS未涉及Not posed 只有确定性技能。Deterministic skills only.
  • Hi-VLA Design Study未涉及Not posed 只有 VLA，但展示了如何更好地调用 VLA。VLA only, though it shows how to call VLAs well.
06方案Proposal

把路由做成显式、可验证的一层Make routing an explicit, verifiable layer

复用现有系统已经验证的模块，把隐式或固定的后端选择推进为显式、可记录、可验证的路由层。 Reuse modules already validated by existing systems, then turn implicit or fixed backend choice into an explicit, logged and verifiable routing layer.
